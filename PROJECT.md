## Теория: Префабы

**Что это:** сохранённый шаблон GameObject со всеми компонентами, свойствами и дочерними объектами. Хранится в `Assets/Prefabs/`.

**Зачем:** создаёте объект один раз — размножаете с одинаковыми настройками; правки в префабе применяются ко всем экземплярам.

**Ключевые понятия:**
- **Экземпляр (instance)** — копия префаба на сцене
- **Override** — локальное изменение экземпляра поверх префаба
- **Apply / Revert** — применить изменения к префабу / откатить к префабу
- **Nested Prefab** — префаб внутри префаба

**В проекте пригодится для:** шарика, блоков, препятствий, снарядов, платформ — всего, что генерируется или повторяется.

---

## Теория: Скрипты на C#

**Что это:** компоненты `MonoBehaviour`, которые вешают поведение на объекты. Файл `.cs` в `Assets/Scripts/`, имя класса = имя файла.

**Базовый каркас:**
```csharp
using UnityEngine;

public class Mover : MonoBehaviour
{
    public float speed = 5f;

    void Start() { /* инициализация */ }

    void Update() { /* каждый кадр */ }

    void FixedUpdate() { /* физика, с постоянным шагом */ }
}
```

**Что важно знать:**
- `Start()` — один раз при старте; `Update()` — каждый кадр; `FixedUpdate()` — шаг физики
- `public`-поля видны в инспекторе; `[SerializeField]` — приватные, но видны
- `GetComponent<T>()` — доступ к компонентам; `Instantiate()` / `Destroy()` — создание/удаление
- События `OnCollisionEnter`, `OnTriggerEnter` — реакция на столкновения

---

## Теория: Управление объектами

**Способы ввода:** `Input.GetAxis("Horizontal"/"Vertical")`, `Input.GetKey`, `Input.GetMouseButton`, новый Input System.

**Движение:**
- `transform.Translate(...)` — прямое перемещение (без физики)
- `Rigidbody.AddForce(...)` / `rigidbody.velocity` — через физику (правильно для шаров, машин)
- `Vector3.MoveTowards`, `Lerp` — плавное движение к цели

**Вращение:** `transform.Rotate(...)`, `Quaternion.LookRotation(...)`

**В проекте:** управление шариком в лабиринте, платформой, «ракеткой» в Pinball, камерой.

---

## Теория: Генерация и движение объектов

**Генерация (спавн):**
```csharp
public GameObject prefab;
public Transform spawnPoint;

void Spawn() {
    Instantiate(prefab, spawnPoint.position, Quaternion.identity);
}
```
- Спавн по таймеру (`InvokeRepeating`), по событию, волнами
- Случайные позиции: `Random.Range`, `Random.insideUnitSphere`

**Движение сгенерированных объектов:**
- Скрипт на префабе двигает его в `Update`/`FixedUpdate`
- `Rigidbody.AddForce` для физичного полёта
- Удаление за границей сцены — `Destroy(gameObject)` в `OnBecameInvisible` или по координатам

**В проекте:** генерация цилиндров, падающее домино, волны препятствий, пирамида шаров.

---

## Теория: Физика, коллизии и триггеры

**Компоненты:**
- **Rigidbody** — massa, drag, gravity, constraints; объект становится физическим
- **Collider** — форма столкновений: `BoxCollider`, `SphereCollider`, `MeshCollider`, `CapsuleCollider`
- **Physic Material** — трение и упругость (bounciness)

**Коллизия vs триггер:**
- Коллизия — объекты сталкиваются физически: `OnCollisionEnter(Collision c)`
- Триггер — зона без физического отталкивания (галочка `Is Trigger`): `OnTriggerEnter(Collider other)`

**Слои (Layers) и `LayerMask`** — чтобы фильтровать, с чем взаимодействуем.

**В проекте:** шары на наклонной поверхности, уничтожение блоков при столкновении, зоны финиша, ловушки.

---

## Теория: Удаление объектов

**Способы:**
- `Destroy(gameObject)` — немедленно в конце кадра
- `Destroy(gameObject, 2f)` — с задержкой
- `SetActive(false)` — выключить, но не удалить (для пула объектов)
- **Object Pooling** — переиспользование вместо постоянного создания/удаления (для производительности)

**Когда удалять:**
- вышел за границу сцены (`OnBecameInvisible`, проверка координат)
- столкнулся с «убивающим» триггером
- истёк таймер жизни
- собран/уничтожен игроком

**В проекте:** уничтожение цилиндров, блоков при столкновении, снарядов за экраном.

---

## Теория: Пользовательское взаимодействие

**Что это:** игрок влияет на сцену — не только двигает персонажа, но и нажимает, выбирает, стреляет, собирает.

**Инструменты:**
- **UI:** Canvas, Button, TextMeshPro, Slider — `OnClick()` в инспекторе или через `button.onClick.AddListener(...)`
- **Рейкаст:** `Physics.Raycast` — клик по 3D-объекту (выбор, стрельба)
- **Триггеры взаимодействия:** подошёл к объекту — сработало событие
- **Счёт, жизни, таймер:** `PlayerPrefs` или собственный `GameManager`

**Паттерн `GameManager`:** один объект-синглтон хранит состояние игры (счёт, уровень, пауза) и события.

**В проекте:** сбор очков, клики по блокам, кнопки старта/рестарта, переключение сцен.

## Теория: Структура проекта и сборка

**Структура папок (рекомендуемая):**
```
Assets/
├── Scenes/         — сцены (Main, Level1, ...)
├── Scripts/        — C#-скрипты по подпапкам (Player, Game, UI)
├── Prefabs/        — префабы
├── Materials/      — материалы
├── Textures/       — текстуры
├── Audio/          — звуки
└── Resources/      — загружаемое по имени (осторожно)
```

**Сборка (Build):**
- `File → Build Settings` → выбрать платформу (PC/WebGL/Android)
- Добавить сцены в `Scenes In Build` в нужном порядке
- `Build` / `Build And Run`
- Проверить сборку **до защиты**, а не на защите

**Git:** `.gitignore` для Unity (исключить `Library/`, `Temp/`, `Build/`), крупные бинарники — через LFS или внешнее хранилище.
